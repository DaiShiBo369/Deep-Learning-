2.1    1.1 CrossEntropyLoss 的输入与目标

     答：不需要先对 logits 做 softmax。 nn.CrossEntropyLoss 的输入应为形状 (N, C) 的原始
logits 和形状 (N, ) 的整数类别目标；它在内部把 log_softmax 与负对数似然（NLL）合并计算，等
价于“先 softmax 再取 − log py ”，但数值更稳定。若先手动 softmax 再传入，相当于重复归一化，
会让梯度变小甚至饱和，是错误用法。
  目标的 dtype 必须是整数类型 torch.long（即 int64），不能是浮点或 one-hot；合法标签范
围是 [0, C − 1]，本题 C = 10，即标签取 0, 1, . . . , 9。超出范围会触发索引错误或未定义行为。

2.2    1.2 model.eval() 是否会关闭梯度计算

   答：不会。model.eval() 只是把模块切换到“推理模式”，改变的是某些层的前向行为：Dropout
停止随机丢弃、BatchNorm 改用训练时累计的 running mean/var 而不是当前 batch 统计量；不影
响 autograd，前向仍会构建计算图、梯度仍可计算。
  torch.no_grad() 才是关闭梯度记录（不构建计算图）的上下文管理器，用于节省显存与计算；
两者的目的不同：eval() 控制“层怎么算”，no_grad() 控制“要不要记录梯度”。推理时通常二者
一起使用：model.eval() + with torch.no_grad():。


2.3    1.3 标量反向传播：x.grad 与 y.grad

      对题目代码，令 x = 2，则 y = 3x = 6，loss = y 2 = 36。由链式法则
                     ∂loss                     ∂loss   ∂loss ∂y
                           = 2y = 12,                =      ·   = 12 × 3 = 36.
                      ∂y                        ∂x      ∂y ∂x

因此 x.grad 为 tensor(36.)。y.grad 默认为 None：PyTorch 只为叶子张量（is_leaf=True，如
这里的 x）累积 .grad，y 是中间结果、不是叶子，因此不保留梯度。
    若要保留 y 的梯度，应在调用 backward() 之前对 y 调用 y.retain_grad()；这样反向传播后
y.grad 为 tensor(12.)。一张计算图被 backward() 释放后不能再次反向传播，演示必须重新做一
次前向。
 x = torch.tensor(2.0, requires_grad=True)
 y = 3 * x
 loss = y ** 2
 loss.backward()
 # x.grad = 36.0, y.grad = None, y.is_leaf = False

 y2 = 3 * x       # fresh graph; x is a leaf
 y2.retain_grad()
 loss2 = y2 ** 2
 loss2.backward()
 # y2.grad = 12.0, x.grad = 36.0

2.4   1.4 分类器末端是 softmax 时能否用 MSE

  数学上可能，但不推荐。若分类器末端为 softmax，输出为概率向量 p = softmax(z)，对 one-hot
                 ∑
目标 t 计算 LMSE = N1 i kpi − ti k2 是完全可定义、可微的复合函数，autograd 也能算出梯度，因
此“可行”。
     但类索引分类通常优先交叉熵：(1) 交叉熵是最大似然/最小化负对数似然，概率解释与训练目
标一致；(2) 梯度性质更好：softmax+ 交叉熵对 logits 的梯度是 p − t，预测错得越离谱梯度越大；
(3) softmax+ 交叉熵对 logits 是凸的，而 softmax+MSE 非凸，优化更困难。因此结论是“可能但
不推荐”

4.3   (c) 重置梯度与训练中清零的原因

   执行 X.grad = None 后重新计算一次 L3 并反向传播，梯度重新从零开始累加，结果又回到 M
（图 8）。
   正常训练每一步要清空梯度，是因为参数梯度默认跨反向传播累加：若不清零，第 k 步的 step()
会使用前 k 个 mini-batch 梯度之和，等效于不断放大学习率并把历史 batch 的信息混入当前更新，
导致更新方向错误。因此标准训练循环在每次 backward() 之前调用 optimizer.zero_grad()（或
把 .grad 置 None），使本次更新只依赖当前 mini-batch。

5.2   4(b) 模型定义

      模型严格为“两个 Linear 层、一个隐藏层”，结构为
                                Flatten    Linear    ReLU      Linear
                      (1, 28, 28) −−−−→ 784 −−−−→ 128 −−−→ 128 −−−−→ 10.

实现中 nn.Flatten() 把每张图展平成 784 维，两个 nn.Linear 分别为 784 → 128 与 128 → 10，中
间接 ReLU；forward 返回形状 (B, 10) 的原始 logits，不接 softmax（softmax 由 CrossEntropyLoss
内部完成）。参数量为 784 × 128 + 128 + 128 × 10 + 10 = 101,770。
 class MLP(nn.Module):
     def __init__(self):
         super().__init__()
         self.flatten = nn.Flatten()
         self.fc1 = nn.Linear(784, 128)
         self.relu = nn.ReLU()
         self.fc2 = nn.Linear(128, 10)

      def forward(self, x):
          x = self.flatten(x)
          x = self.fc1(x)
          x = self.relu(x)
          return self.fc2(x)

5.3   4(c) 损失、反向传播与训练

    损失函数为 nn.CrossEntropyLoss()，优化器为 torch.optim.SGD(model.parameters(),
lr=0.1)。train_one_epoch 的核心循环如下（每个 batch）：
 model.train()
 for images_batch, labels_batch in loader:
     optimizer.zero_grad()                 # 1. 清空上一步的梯度
     logits = model(images_batch)          # 2. 前向
     loss = loss_fn(logits, labels_batch) # 3. 计算交叉熵
     loss.backward()                       # 4. 反向传播，计算梯度
     optimizer.step()                      # 5. 用梯度更新参数
     total_loss += loss.item() * labels_batch.size(0)
     total_correct += (logits.argmax(dim=1) == labels_batch).sum().item()
     total_examples += labels_batch.size(0)


    哪一行计算梯度、哪一行更新参数：loss.backward() 依据计算图做反向传播，把 ∂L/∂θ 累
加到每个参数的 .grad 上，它不改变参数值；optimizer.step() 才读取这些梯度并按 SGD 规则
θ ← θ − η ∂L/∂θ 修改参数。二者之间还有 optimizer.zero_grad()：因为 .grad 默认累加，不清
零会让多个 batch 的梯度混在一起，所以每个 batch 开始时先清零。
